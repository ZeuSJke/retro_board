# Bugfix Workflow

## Применение

**Когда использовать:** Исправление бага, ошибка в runtime, неожиданное поведение.

**Кто запускает:** Разработчик или QA

---

## Последовательность

### Шаг 1 — @explainer: Анализ

**Цель:** Найти root cause проблемы

**Делает:**
- Изучает код связанный с багом
- Воспроизводит проблему (если возможно)
- Находит root cause
- Предлагает решение

**Выход:**
- Описание root cause
- Файл и строка где проблема
- Предложенное решение

**Критерии завершения:**
- [ ] Root cause найден
- [ ] Решение предложено

---

### Шаг 2 — @backend-dev или @frontend-dev: Исправление

**Цель:** Исправить код

**Делает (для backend):**
- Вносит исправление в `models.py`, `schemas.py`, `routers/`, etc.
- Проверяет что не сломалось ничего другого

**Делает (для frontend):**
- Вносит исправление в `components/`, `hooks/`, `store/`, etc.
- Проверяет что UI работает

**После завершения:**

```bash
cd backend && python -m pytest -v
cd frontend && npm run lint && npm run build
```

**Критерии завершения:**
- [ ] Код исправлен
- [ ] Тесты проходят

---

### Шаг 3 — @qa: Верификация

**Цель:** Проверить что баг исправлен

**Делает:**
- Запускает тесты связанные с исправлением
- Проверяет edge cases
- Обновляет или добавляет тесты если нужно

**После завершения:**

```bash
cd backend && python -m pytest -v -k "test_name"
cd frontend && npm test
```

**Критерии завершения:**
- [ ] Баг исправлен и verified
- [ ] Регрессий нет
- [ ] Новые тесты написаны если нужно

---

## Критерии завершения workflow

- [ ] Root cause найден
- [ ] Код исправлен
- [ ] Тесты проходят
- [ ] Баг больше не воспроизводится

## Важно

Если баг требует архитектурного изменения — вызываем @architect перед @backend-dev.

Если нужно добавить новую функциональность — используй Feature Development Workflow.
