# Feature Development Workflow

## Применение

**Когда использовать:** Новая функциональность, новая сущность, новый API эндпоинт, новая UI фича.

**Кто запускает:** Разработчик или Tech Lead

---

## Последовательность

### Шаг 1 — @architect: Проектирование

**Цель:** Спроектировать схему данных и API контракт

**Делает:**
- Изучает существующие модели и роутеры
- Анализирует требования к новой фиче
- Проектирует новую сущность или изменение
- Предлагает API контракт (если нужен)
- Определяет WebSocket события (если нужно)
- Пишет план Alembic миграции

**Выход:**
- Описание изменений (файлы, эндпоинты)
- План миграции (если нужно)
- WebSocket события (если нужно)

**Критерии завершения:**
- [ ] Схема данных утверждена
- [ ] API контракт описан
- [ ] Миграция спланирована

---

### Шаг 2 — @backend-dev: Бэкенд

**Цель:** Реализовать бэкенд логику

**Делает:**
- Создаёт/изменяет модель в `models.py`
- Создаёт/изменяет схему в `schemas.py`
- Создаёт/изменяет роутер в `routers/`
- Подключает роутер в `main.py`
- Добавляет WebSocket events (если нужно)
- Добавляет в KNOWN_EVENTS (если нужно)
- Создаёт Alembic миграцию

**После завершения:**

```bash
cd backend
python -m pytest -v
```

**Критерии завершения:**
- [ ] pytest проходит
- [ ] Миграция создана
- [ ] Код соответствует архитектуре

---

### Шаг 3 — @frontend-dev: Фронтенд

**Цель:** Реализовать UI

**Делает:**
- Создаёт/изменяет компонент в `components/`
- Обновляет типы в `types/index.ts`
- Добавляет API функцию в `api/index.ts`
- Добавляет WebSocket обработку (если нужно)
- Создаёт/обновляет CSS Module

**После завершения:**

```bash
cd frontend
npm run lint
npm run build
npm test
```

**Критерии завершения:**
- [ ] lint проходит
- [ ] build успешен
- [ ] тесты проходят

---

### Шаг 4 — @security: Аудит безопасности

**Цель:** Проверить изменения на уязвимости

**Делает:**
- Анализирует новый код на OWASP Top 10
- Проверяет валидацию входных данных
- Проверяет аутентификацию и авторизацию
- Проверяет rate limiting

**Критерии завершения:**
- [ ] Нет SQL injection
- [ ] Нет XSS
- [ ] Auth работает правильно
- [ ] Rate limiting применён

---

### Шаг 5 — @qa: Тестирование

**Цель:** Написать тесты и проверить coverage

**Делает:**
- Пишет unit тесты для бэкенда (pytest)
- Пишет unit тесты для фронтенда (Vitest)
- Проверяет edge cases
- Запускает E2E тесты если нужно

**После завершения:**

```bash
cd backend && python -m pytest -v
cd frontend && npm test
```

**Критерии завершения:**
- [ ] Все тесты проходят
- [ ] Coverage не упал
- [ ] Edge cases покрыты

---

## Критерии завершения workflow

- [ ] Фича реализована
- [ ] Тесты написаны и проходят
- [ ] Безопасность проверена
- [ ] Документация обновлена (если нужно)

## Важно

Если на шаге 4 (@security) найдены проблемы — вернуться к шагу 2 или 3 для исправления.

Если на шаге 5 (@qa) тесты падают — вернуться к соответствующему шагу.
